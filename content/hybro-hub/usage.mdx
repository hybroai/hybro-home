# Usage

## Run the daemon

Start in the background:

```bash
hybro-hub start --api-key hybro_...
```

A key passed with `--api-key` is saved to `~/.hybro/config.yaml`, unless that field is an environment reference. In the background, logs go to `~/.hybro/hub.log` (rotating, 10 MB × 3); with `--foreground` they print to the terminal.

Only one Hub daemon runs per machine (lock file `~/.hybro/hub.lock`). `stop` sends SIGTERM, waits 10 seconds, then sends SIGKILL. `restart --foreground` (or `-f`) restarts the daemon attached to the terminal.

Useful lifecycle commands:

```bash
hybro-hub start --foreground   # stay attached for debugging
hybro-hub status               # daemon, relay, and agent status
hybro-hub agents               # discovered local agents
hybro-hub restart
hybro-hub stop
hybro-hub --version
```

Enable debug logging with `hybro-hub -v start`.

## Configuration

Hybro Hub reads `~/.hybro/config.yaml`:

```yaml
cloud:
  api_key: ${HYBRO_API_KEY}
  gateway_url: "https://api.hybro.ai"

agents:
  auto_discover: true
  auto_discover_exclude_ports:
    - 22
    - 53
    - 80
    - 443
    - 3306
    - 5432
    - 6379
    - 27017
  # auto_discover_scan_range: [10000, 11000]
  local:
    - name: "My Custom Agent"
      url: "http://localhost:9001"

privacy:
  sensitive_keywords: ["medical", "financial", "confidential"]
  sensitive_patterns: ["PROJ-\\d{4}"]

publish_queue:
  enabled: true
  max_size_mb: 50
  ttl_hours: 24
  drain_interval: 30
  drain_batch_size: 20
  max_retries_critical: 20
  max_retries_normal: 5

heartbeat_interval: 30
dispatcher_read_timeout_secs: 300
```

Environment references are expanded before YAML parsing:

| Syntax | Meaning |
| --- | --- |
| `${VAR}` | Environment value, or an empty string when unset |
| `${VAR:-default}` | Environment value, or the supplied default |
| `$${VAR}` | Literal `${VAR}` |

`HYBRO_API_KEY` and `HYBRO_GATEWAY_URL` also override the corresponding config values at startup.

Unknown configuration keys produce warnings, and invalid values fail with a readable configuration error.

## Agent discovery

With `auto_discover: true`, the Hub lists listening localhost ports with OS tools (`lsof` on macOS, `/proc/net/tcp` on Linux, psutil on Windows), skips `auto_discover_exclude_ports`, and probes:

- `/.well-known/agent-card.json`
- `/.well-known/agent.json`

Cards are validated with the A2A SDK (A2A v0.3 or v1.0) and must expose a JSON-RPC interface. Discovery runs at startup and every 120 seconds. Agents are health-checked every 60 seconds and removed after 3 consecutive failures.

If the OS tools fail, the Hub falls back to a TCP connect-scan of ports 1024–65535. `auto_discover_scan_range` narrows only that fallback scan:

```yaml
agents:
  auto_discover_scan_range: [10000, 11000]
```

To keep a port out of discovery, add it to `auto_discover_exclude_ports`.

Manually configured localhost or LAN agents are always probed even when auto-discovery is disabled; only reachable agents with valid A2A cards and a JSON-RPC interface are registered. Auto-discovery scans localhost only, so add LAN agents under `agents.local`.

## Launch an agent

`hybro-hub agent start` supports these adapters:

| Adapter type | Underlying runtime | Streaming |
| --- | --- | ---: |
| `ollama` | Ollama | Yes |
| `openclaw` | OpenClaw | No |
| `n8n` | n8n webhook | No |
| `claude-code` | Claude Code CLI | Yes |
| `codex` | Codex CLI | No |
| `hermes` | Hermes Agent | Yes |

### Ollama

```bash
hybro-hub agent start ollama
hybro-hub agent start ollama --model mistral:7b --port 10020 \
  --system-prompt "You are a helpful assistant"
```

With the `ollama` shortcut, the Hub checks that Ollama at `http://localhost:11434` is reachable and the model is pulled. YAML configs (`--config`) skip this check.

### Claude Code and Codex

```bash
hybro-hub agent start claude-code --working-dir /path/to/project
hybro-hub agent start codex --working-dir /path/to/project
```

Use `--claude-path` or `--codex-path` when the executable is not on `PATH`.

### OpenClaw

```bash
hybro-hub agent start openclaw
hybro-hub agent start openclaw --thinking medium --agent-id main
```

### n8n

```bash
hybro-hub agent start n8n \
  --webhook-url http://localhost:5678/webhook/my-agent
```

### Hermes

Put a Hermes Agent checkout on `PYTHONPATH` and run `hermes setup`, then:

```bash
export PYTHONPATH=/path/to/hermes-agent:$PYTHONPATH
hybro-hub agent start hermes
hybro-hub agent start hermes \
  --model anthropic/claude-sonnet-4 \
  --enabled-toolsets hermes-cli
```

## Agent YAML files

Use `--config` for the full adapter surface:

```bash
hybro-hub agent start --config hybro-agent.yaml
```

If `hybro-agent.yaml` or `.hybro-agent.yaml` exists in the current directory, running `hybro-hub agent start` without arguments selects it automatically.

Example:

```yaml
adapter: ollama
name: "My Ollama Agent"
port: 10010
model: llama3.2
base_url: http://localhost:11434
system_prompt: "You are a helpful assistant"
temperature: 0.7
timeout: 120
keep_alive: "5m"
```

With `--config`, these flags override file values: `--port`, `--name`, `--timeout`, `--working-dir`, `--claude-path`, `--codex-path`, `--provider`, and `--enabled-toolsets`. Other adapter flags (`--model`, `--system-prompt`, `--thinking`, `--agent-id`, `--openclaw-path`, `--webhook-url`) are ignored; set them in the file. `--config` cannot be combined with an adapter argument, and the file must contain `adapter:`.

## Update the Hub

```bash
hybro-hub update --dry-run
hybro-hub update
hybro-hub update --restart
```

The update command checks and upgrades `hybro-hub`, `a2a-adapter`, and `a2a-sdk` using the detected installer.

## Privacy and reliability

Privacy classification detects common PII, API keys, custom keywords, and regular expressions. **It currently logs detections only; it does not block, anonymize, or reroute messages.**

Failed outbound events can be queued in a disk-backed SQLite store and retried. Critical and normal events have separate retry limits, while TTL and size limits bound the queue.
