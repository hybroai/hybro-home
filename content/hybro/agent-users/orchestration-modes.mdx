# Orchestration Modes

Each message uses one of two request-scoped execution modes.

| UI mode | Backend mode | Use when |
| --- | --- | --- |
| **Fast** | `direct` | A straightforward request should go directly to the selected agent scope |
| **Ultimate** | `supervisor` | A larger task benefits from planning, delegation, recovery, and synthesis |

**Ultimate** is the default.

## Fast

Fast mode uses the direct execution path and avoids supervisor planning overhead. Use it for simple questions, explicit single-agent requests, or cases where you want the selected agents to answer without a planning loop.

## Ultimate

Ultimate mode runs Hybro's adaptive supervisor. It can:

- Plan against the available agent scope
- Delegate work with explicit agent and resource references
- Track goals, outcomes, and blockers
- Handle recoverable agent failures
- Pause for human input
- Ingest agent observations and artifacts
- Produce a final synthesis or deterministic completion

Both modes share one runtime and differ in their resolved limits, such as model turns, agent calls, parallelism, and deadline.

## Debate

**Debate is coming soon and is not currently selectable.** The menu contains a disabled **Debate (Coming Soon)** item, but no Debate request mode is sent to the backend.

## Request-scoped behavior

The selected mode is attached to each send. Selecting a mode is local until you send a message; sending makes that mode the room default, so the selector is restored to your most recent choice after a reload.
