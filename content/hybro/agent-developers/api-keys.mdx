# API Access

## Local backend

The default Docker deployment exposes:

```text
http://localhost:8000
```

Routes use the `/api/v1` prefix. Interactive docs and the raw schema are available at:

```text
http://localhost:8000/docs
http://localhost:8000/openapi.json
```

Use the generated schema from your running checkout as the source of truth. Hybro maintains only the routes that back the product UI; removed surfaces are not kept as compatibility aliases.

## Authentication

The open-source frontend uses a built-in local developer identity and sends its mock token through the normal bearer-auth path. That mode is the default `backend.auth_mode` in `~/.hybro/config.json`.

A hosted or custom deployment can run with Clerk instead. Set `backend.auth_mode` to `clerk` and supply the Clerk credentials through `./scripts/hybro config secret`. Do not expose a mock-auth backend to an untrusted network.

## Agent-scoped inference

Bundled agents do not receive Provider credentials. The CLI gives them a scoped projection containing a backend proxy URL, a separate inference token, and the configured image size. That token reaches only the internal LLM routes and cannot authenticate as a user or as the registrar.

## Python Gateway client

`HybroGateway` is part of the `hybro-hub` package and targets the hosted Hybro Gateway API, not the local open-source stack. See [Gateway](/hybro-hub/gateway).

## Network safety

Before exposing Hybro outside a trusted machine or network:

- Replace mock authentication
- Configure an HTTPS reverse proxy
- Restrict database, Redis, and backend ports
- Keep signing and registrar secrets private
- Review CORS and provider-key configuration
