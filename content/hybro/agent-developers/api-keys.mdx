# API Access

## Local backend

The default Docker deployment exposes:

```text
http://localhost:8000
```

Routes use the `/api/v1` prefix. Interactive docs and the raw schema are available at:

```text
http://localhost:8000/docs
http://localhost:8000/openapi.json
```

Use the generated schema from your running version as the source of truth. Besides the routes behind the UI, Hybro exposes an agent-network API and a sessions API for external clients; see [Connect over MCP or HTTP](/docs/hybro/agent-developers/connect). Removed surfaces are not kept as compatibility aliases.

## Authentication

The open-source frontend uses a built-in local developer identity and sends its mock token through the normal bearer-auth path. That mode is the default `backend.auth_mode` in `~/.hybro/config.json`. In mock mode, REST clients need no token.

A hosted or custom deployment can run with Clerk instead. Set `backend.auth_mode` to `clerk`, store the secret with `hybro config secret clerk_secret_key` (and optionally `clerk_webhook_secret`), and set `frontend.clerk_publishable_key`. Startup fails when `auth_mode` is `clerk` without the secret. The MCP server does not work with Clerk. Do not expose a mock-auth backend to an untrusted network.

## Agent-scoped inference

Bundled agents do not receive Provider credentials. The CLI gives them a scoped projection containing a backend proxy URL, a separate inference token, and the configured image size. That token reaches only the internal LLM routes (`/api/v1/internal/llm`) and cannot authenticate as a user or as the registrar.

## Python Gateway client

`HybroGateway` is part of the `hybro-hub` package and targets the hosted Hybro Gateway API, not the local open-source stack. See [Gateway](/docs/hybro-hub/gateway).

## Network safety

Before exposing Hybro outside a trusted machine or network:

- Replace mock authentication
- Configure an HTTPS reverse proxy
- Restrict database, Redis, and backend ports. Compose publishes MongoDB (27017) and Redis (6379) on all interfaces
- Do not expose the MCP server; it has no authentication
- Deny `/api/v1/internal/llm` to callers other than your agents at your ingress
- Keep signing and registrar secrets private
- Review CORS and provider-key configuration
