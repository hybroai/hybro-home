# Installation

Hybro's open-source stack runs with Docker Compose. It includes the Next.js frontend, FastAPI backend, MongoDB 7 replica set, Redis, persistent room-file storage, four example agents, and a one-shot registrar.

## Prerequisites

- Git
- Docker with Compose v2.24+ (`docker compose`)

The legacy `docker-compose` v1 binary is not supported.

For native development, use Node.js 20.19+, Python 3.12+, and MongoDB 4.2+.

## Install with the script

```bash
curl -fsSL https://raw.githubusercontent.com/hybroai/hybro/main/install.sh | sh
```

The installer clones or updates `${INSTALL_DIR:-$HOME/hybro}`, prepares the repo-root environment, generates required secrets and default-agent services, then starts a freshly built stack.

Choose another directory with:

```bash
INSTALL_DIR=/path/to/hybro \
  sh -c "$(curl -fsSL https://raw.githubusercontent.com/hybroai/hybro/main/install.sh)"
```

Existing installations that used `backend/.env`, `frontend/.env.local`, or `default_agents/.env` are migrated to the current repo-root configuration. The old frontend file is backed up as `frontend/.env.local.legacy` before regeneration.

## Install manually

```bash
git clone https://github.com/hybroai/hybro.git
cd hybro
./scripts/hybro start
```

A fresh clone can start without an `.env`. This is the zero-config demo path: Hybro uses mock authentication, but bundled agents and LLM-backed orchestration fail until `OPENAI_API_KEY` is configured.

## Configure model access

The repo-root `.env` is the single source of truth for the backend, bundled agents, and frontend build configuration. Create it from the example and set at least the OpenAI key:

```bash
cp .env.example .env
# Edit .env and set OPENAI_API_KEY
./scripts/hybro start --recreate
```

`./scripts/hybro start` generates webhook and registrar secrets when needed, renders the default-agent Compose services from `default_agents/agents.yaml`, and regenerates `frontend/.env.local`. Do not hand-edit `frontend/.env.local`.

The bundled agents still register without an OpenAI key, but calls that use OpenAI fail until a valid key is configured. The default manifest starts Weather, Image Generator, Travel Planner, and Story agents.

If you change a runtime setting in `.env`, use `--recreate`. If you change a `NEXT_PUBLIC_*` value, rebuild as well because those values are baked into the frontend image:

```bash
./scripts/hybro start --build --recreate
```

Use `--check-key` to fail fast when `.env` or `OPENAI_API_KEY` is not ready:

```bash
./scripts/hybro start --check-key
```

## Manage the stack

Use `./scripts/hybro` for day-to-day lifecycle operations:

```bash
./scripts/hybro status          # Show all container states
./scripts/hybro logs backend    # Stream one service; omit it for all services
./scripts/hybro restart backend # Restart one service; omit it for the full stack
./scripts/hybro stop            # Stop containers but keep them
./scripts/hybro down            # Remove containers and the default network
```

Run `./scripts/hybro --help` for the complete command reference. Named volumes remain intact after `stop` or `down`; avoid `./scripts/hybro down -v` unless you intend to delete local data.

## Update

```bash
cd ~/hybro   # or your INSTALL_DIR
git pull
./scripts/hybro start --build --recreate
```

The `mongo_data`, `redis_data`, and `room_files` volumes persist across container recreation.
