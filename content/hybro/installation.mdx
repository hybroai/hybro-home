# Installation

Hybro runs as one container from one image. The image holds the Next.js frontend, the FastAPI backend, an embedded MongoDB 7 replica set, room-file storage, the MCP adapter, and the bundled agents, with Caddy serving them on one port. The `hybro` command is a small shell script that starts it with Docker.

## Prerequisites

| You need | When |
| --- | --- |
| Docker (Docker Desktop on macOS, Docker Engine on Linux), amd64 or arm64 | Always |
| An API key for OpenAI, DeepSeek, or Anthropic, or a ChatGPT account | For Room Chat and the LLM-backed agents; Echo Agent and MCP work without one |
| Node.js | Only to install the CLI with npm |
| Node.js 24+, Python 3.12+, and MongoDB 4.2+ | Only to run the frontend or backend outside Docker |

## Install

```bash
curl -fsSL https://hybro.ai/install.sh | sh
hybro
```

`install.sh` downloads the `hybro` script from the latest release, verifies it against the release's `SHA256SUMS`, installs it into `~/.local/bin` (or a writable `/usr/local/bin` when `~/.local/bin` is not on `PATH`), and pulls the image. It never uses `sudo` and never edits shell profiles; if the directory is not on `PATH`, it prints the line to add.

With npm instead:

```bash
npm install -g @hybroai/cli
hybro
```

Both install the same script.

`hybro` (or `hybro start`) pulls the image for its own version, starts the container, prints the address, and follows the logs; Ctrl-C stops Hybro. `hybro start -d` runs it in the background.

## Released install or source checkout

| | Released install | Source checkout |
| --- | --- | --- |
| Use it to | Try or use Hybro | Change Hybro |
| Command | `hybro` | `./scripts/hybro` |
| Image | `ghcr.io/hybroai/hybro:<version>`, pulled | `hybro:dev`, built from your working tree |
| Container | `hybro` | `hybro-dev` |
| Data volume | `hybro-data` | `hybro-dev-data` |
| App, API, and MCP | [http://localhost:3000](http://localhost:3000) | [http://localhost:3100](http://localhost:3100) |
| Updates | Daily notice; `hybro upgrade` | `git pull`, then `./scripts/hybro start --build --recreate` |

From a checkout:

```bash
git clone https://github.com/hybroai/hybro.git
cd hybro
./scripts/hybro
```

The first build takes several minutes; later starts reuse the image until you pass `--build`. In a checkout, use `./scripts/hybro` wherever these docs show `hybro`. Both read the same `~/.hybro/` configuration, so a provider saved in one is used by the other, and both can run at once.

## Open Hybro

Open the address that `hybro` prints. One port serves everything:

| Path | What |
| --- | --- |
| `/` | The Hybro app |
| `/api/v1` | The backend API |
| `/health` | Backend health check |
| `/mcp` | The MCP server (Streamable HTTP, loopback listener only) |

The app opens on **Overview** (`/`): Sessions, Chats, Agents, and MCP gateway tiles, recent sessions and chats, a mini network map, and the most-called agents. Until a model provider is set up, a banner links to **Settings**; see [Getting Started](/docs/hybro/agent-users/getting-started).

If the page does not load, check Hybro with `hybro status` and `hybro logs`.

## Run Hybro

```bash
hybro                        # Start and follow the logs; Ctrl-C stops Hybro
hybro start -d               # Start in the background
hybro start --port 4000      # Another host port (default 3000; 3100 from a checkout)
hybro status                 # Running or not, with the address
hybro logs -f                # Follow the logs; docker logs options pass through
hybro stop                   # Stop; data stays in the volume
hybro upgrade                # Newest release, its image, and any 0.3 migration
hybro version
```

Start options are flags only; environment variables do not become a second configuration source. Configuration changes apply after `hybro stop` and `hybro`, except the model provider, which applies at once. From a checkout, `./scripts/hybro start --build` rebuilds `hybro:dev` and `--recreate` replaces a running container. Run `hybro help` for the full command reference.

## Run on a server

`hybro` listens on `127.0.0.1` by default. `--listen <address>` serves the app on another address:

```bash
hybro start -d --listen 0.0.0.0 --port 443
```

A non-loopback listener requires sign-in (`backend.auth_mode` set to `clerk`, see [API access](/docs/hybro/agent-developers/api-keys)) and a `frontend.server_url`, or the explicit `--insecure-no-auth` for a trusted network. MCP is served only on a loopback listener, because it has no authentication.

## Bundled agents

The image runs five agents, and the backend registers them at startup:

- **Echo Agent** repeats your message and needs no model provider, so it works right after install.
- **Weather Agent**, **Story Agent**, **Travel Planner Agent**, and **Image Generator Agent** stay inactive, with the reason shown on their cards, until a model provider is set up. Image Generator Agent also needs an image model, which requires an OpenAI API key.

## Upgrade

```bash
hybro upgrade --check    # Report; exits non-zero when a newer release exists
hybro upgrade
```

`hybro upgrade` downloads the newest script, checks it against `SHA256SUMS`, and replaces itself the way it was installed (through npm for an npm install), then pulls the new image. A running container is started again on the new image with the same port and listener. Once a day `hybro` also prints a one-line notice when a newer release exists; `HYBRO_NO_UPDATE_CHECK=1` turns it off.

A checkout is updated with `git pull` and `./scripts/hybro start --build --recreate`.

## Upgrade from 0.3

Hybro 0.3 ran a Docker Compose stack whose data lives in the `hybro_mongo_data` and `hybro_room_files` volumes (`hybro-dev_*` for a checkout). If you installed 0.3 with npm, run the 0.3 command `hybro upgrade` first; it installs the 0.4 script.

The first `hybro` on 0.4 finds the 0.3 data, starts nothing, and offers two choices:

```bash
hybro upgrade      # Copy the 0.3 data into the new volume
hybro --fresh      # Or start with an empty volume and keep the old data aside
```

The migration stops the 0.3 containers, checks that Docker has twice the 0.3 data size free, copies MongoDB and room files into `hybro-data` from read-only mounts, and starts Hybro. Redis data is not migrated; it held only transient state. `config.json` and `auth.json` stay where they are, so a provider set up in 0.3 carries over. If the 0.3 install used a custom app port, the output shows the `--port` value that keeps it.

The 0.3 volumes are only read, never changed. An interrupted migration is detected on the next `hybro`, and `hybro upgrade` starts the copy over. After checking your data, remove the 0.3 containers, volumes, and images:

```bash
hybro cleanup-old
```

### Roll back to 0.3

1. Run `hybro stop`.
2. Remove `admin_user_ids` from `config.json` if you set it, because 0.3 rejects unknown keys. 0.3 also requires a configured model provider.
3. Reinstall 0.3.0 with `npm install -g @hybroai/cli@0.3.0`, or unpack the `hybro-0.3.0-<platform>.tar.gz` archive from the [0.3.0 release](https://github.com/hybroai/hybro/releases/tag/v0.3.0), then run `hybro start`.

0.3 finds its data as it was at the migration. Rooms, sessions, and agents created in 0.4 are not carried back.

## Uninstall

```bash
hybro stop
docker rm hybro && docker volume rm hybro-data   # Deletes all Hybro data
rm "$(command -v hybro)"                          # Or: npm uninstall -g @hybroai/cli
```

`~/.hybro` holds the configuration and credentials; delete it to remove those too.
