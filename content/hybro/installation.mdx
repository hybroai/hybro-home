# Installation

Hybro's open-source stack runs with Docker Compose. It includes the Next.js frontend, the FastAPI backend, a MongoDB 7 replica set, Redis, persistent room-file storage, four example agents, and a one-shot registrar.

## Prerequisites

- Git
- Docker with Compose v2.24+ (`docker compose`)

The legacy `docker-compose` v1 binary is not supported.

- [uv](https://docs.astral.sh/uv/) — the `./scripts/hybro` CLI runs its configuration tool through uv.

For native development outside Docker, use Node.js 20.19+, Python 3.12+, and MongoDB 4.2+ (Docker Compose pins MongoDB 7.0).

## Install with the script

```bash
curl -fsSL https://raw.githubusercontent.com/hybroai/hybro/main/install.sh | sh
```

The installer requires `git`, `docker`, and `uv`. It clones or updates `${INSTALL_DIR:-$HOME/hybro}`, prints the setup and start commands, and opens the interactive CLI when a terminal is attached. It does not create environment files, generate secrets, build images, or start services.

Choose another directory with:

```bash
INSTALL_DIR=/path/to/hybro \
  sh -c "$(curl -fsSL https://raw.githubusercontent.com/hybroai/hybro/main/install.sh)"
```

## Install manually

```bash
git clone https://github.com/hybroai/hybro.git
cd hybro
./scripts/hybro setup
./scripts/hybro start --build
```

A fresh checkout cannot start before it is configured. Running `./scripts/hybro start` without configuration stops with a message pointing at `./scripts/hybro setup` (or `config migrate` for an older YAML setup).

## Configure Hybro

Hybro keeps backend, frontend, and bundled-agent settings in one local JSON directory instead of repository environment files:

```text
~/.hybro/
├── config.json   # User settings and Provider/model selection
└── auth.json     # Provider credentials and scoped service tokens
```

```bash
./scripts/hybro setup          # Choose a Provider, authenticate, select models
./scripts/hybro start --build  # Build and start the stack
```

See [Configuration](/docs/hybro/configuration) for the full contract, the `config` commands, and the one-time migration from an older setup.

| Service | URL |
| --- | --- |
| Hybro app | [http://localhost:3000](http://localhost:3000) |
| API server | [http://localhost:8000](http://localhost:8000) |
| Health check | [http://localhost:8000/health](http://localhost:8000/health) |
| Interactive API docs | [http://localhost:8000/docs](http://localhost:8000/docs) |

The app opens on the Hybro Core page. The open-source frontend uses a built-in local developer identity, so the default Docker deployment does not require account setup.

## Manage the stack

`./scripts/hybro` is the day-to-day lifecycle CLI:

```bash
./scripts/hybro start                     # Start services, no rebuild (fast daily loop)
./scripts/hybro start --build             # Rebuild images (after code or dependency changes)
./scripts/hybro start --recreate          # Recreate containers (runtime configuration changes)
./scripts/hybro start --build --recreate  # Rebuild and recreate (public frontend or image changes)
./scripts/hybro status                    # Show all containers, including stopped ones
./scripts/hybro logs backend              # Follow one service; omit the name for all
./scripts/hybro logs --container <name>   # Follow one exact container or replica
./scripts/hybro restart backend           # Restart one service; omit the name for the stack
./scripts/hybro stop                      # Stop containers but keep them
./scripts/hybro down                      # Remove containers and the default network
```

`start` also generates missing internal service tokens and regenerates the default-agent Compose services from `default_agents/agents.yaml`.

Named volumes remain intact after `stop` or `down`; avoid `./scripts/hybro down -v` unless you intend to delete local data.

Run `./scripts/hybro --help` for the complete command reference. Running `./scripts/hybro` with no command opens the interactive Models/Services UI when a terminal is available; otherwise it prints that same help text.

## Bundled agents

The default manifest starts Weather, Image Generator, Travel Planner, and Story, plus a one-shot registrar that registers them with the backend on startup.

Registration itself does not need a Provider credential. Calls that use a model — the bundled agents and Hybro's own orchestration — need the Provider configured through `./scripts/hybro setup`.

## Update

```bash
cd ~/hybro   # or your INSTALL_DIR
git pull
./scripts/hybro start --build --recreate
```

The `mongo_data`, `redis_data`, and `room_files` volumes persist across container recreation.
