# Configuration

Hybro reads one JSON configuration for the backend, the frontend, and the bundled agents. Start options such as the port and listener are `hybro` flags; see [Installation](/docs/hybro/installation#run-hybro).

## Configuration files

```text
~/.hybro/
├── config.json   # User settings; the Settings page or a text editor
└── auth.json     # Credentials; the Settings page and the container manage it
```

`HYBRO_HOME` relocates that directory and must be an absolute path. Hybro creates the directory with mode `0700`; `auth.json` requires mode `0600`. A released install and a source checkout read the same directory.

`config.json` holds the shared user configuration. It only needs the values you override:

| Field | Purpose |
| --- | --- |
| `version` | Configuration format version; always `1` |
| `provider` | Provider ID (`openai`, `deepseek`, `anthropic`) and authentication method (`api_key` or `oauth`); set from **Settings** |
| `models` | Selected text model, and an image model when the connection supports one; set from **Settings** |
| `backend` | Deployment overrides such as `log_level`, `auth_mode`, or local discovery settings |
| `frontend` | Public frontend overrides such as `max_message_length` |
| `image_size` | Generated image size: `1024x1024`, `1536x1024`, `1024x1536`, or `auto` |

Startup validates JSON syntax, known fields, types, ranges, and required combinations, and reports safe field-level errors. A missing model provider is allowed: Room Chat and the LLM-backed agents stay inactive and the app points to **Settings**. `backend` accepts deployment settings only; credentials belong in `auth.json`, and the provider and models are set from **Settings**.

Repository `.env` files are not read. The container's entrypoint gives each service only its own scoped settings; secrets never enter the browser bundle and are never forwarded wholesale to agents.

## Model provider

Set up the model provider in the app: **Settings**, **Model provider** (also under your name at the bottom of the sidebar).

| Provider | Authentication | Notes |
| --- | --- | --- |
| OpenAI | ChatGPT sign-in or API key | Image generation requires the API-key connection |
| Anthropic | API key | |
| DeepSeek | API key | |

**Check and save** verifies an API key with one small request before saving it to `auth.json`. The provider and models apply at once, without a restart; a new image size applies after `hybro stop` and `hybro`. See [Getting Started](/docs/hybro/agent-users/getting-started#2-set-up-a-model-provider) for the steps.

## Edit configuration

Edit `~/.hybro/config.json`, then restart:

```json
{
  "version": 1,
  "backend": { "log_level": "DEBUG" },
  "frontend": { "max_message_length": 12000 }
}
```

```bash
hybro stop && hybro
```

Settings other than the model provider are a startup snapshot. Edits from the Settings page use the same validation before saving; manual edits are validated at the next start. Startup generates missing internal tokens in `auth.json` without rotating existing ones.

## Model access for agents

Bundled agents never receive Provider credentials or the configuration directory. Each one gets a scoped projection with the backend's model proxy URL, a separate inference token, and the image size. The token cannot authenticate as a user.

## Backend fields

Waits for the owner or for a remote agent:

| Field | Default | Meaning |
| --- | --- | --- |
| `backend.approval_deadline_hours` | `null` (no deadline) | Hours before an unanswered supervisor question expires and fails its run. Must be greater than 0 when set |
| `backend.orchestrator_call_wait_ceiling_hours` | `168` (seven days) | Hours an acknowledged remote agent task is polled with `tasks/get` before the call expires. Must be greater than 0 |
| `backend.a2a_push_callback_base_url` | `""` (push disabled) | Base URL that remote agents can reach. Must be `https`; plain `http` is accepted only for loopback, `host.docker.internal`, or a private RFC 1918 address, because the per-call push token travels in a request header. When set, Hybro registers a push notification URL with agents whose card advertises push support, so late results arrive without waiting for the next poll. Polling stays the fallback |

```json
{
  "backend": {
    "approval_deadline_hours": 48,
    "orchestrator_call_wait_ceiling_hours": 72.5,
    "a2a_push_callback_base_url": "https://hybro.example.com"
  }
}
```

A run waiting for an answer or a remote agent does not count that time against its mode's deadline, so it can wait as long as these limits allow. While it waits, it keeps the room's single active-run slot.

Passthrough runs (session sends, no orchestrator model turns):

| Field | Default | Meaning |
| --- | --- | --- |
| `backend.orchestrator_passthrough_deadline_seconds` | `300` | Active seconds a passthrough run may take; waiting for the owner or a remote agent does not count |
| `backend.orchestrator_passthrough_max_transport_retries_per_call` | `2` | Transport retries for the single agent call |

Sessions:

| Field | Default | Meaning |
| --- | --- | --- |
| `backend.session_run_start_grace_seconds` | `10` | Seconds after a send without any lifecycle event before the session reports `failed` with `run_not_started` |

Other common fields include `backend.auth_mode` (`mock` or `clerk`), `backend.log_level`, `backend.log_format` (`auto`, `json`, or `logfmt`), and the `backend.local_agent_discovery_*` settings. In the image, local discovery is on by default and scans `host.docker.internal` ports 1024–65535 every 120 seconds, skipping the bundled agents' ports.

## Frontend fields

`frontend` accepts only known public keys, including `api_base_url`, `server_url`, the `clerk_*` sign-in settings, `enable_waitlist`, `max_message_length` (default `10000`), and `inspection_timeout_ms` (default `300000`). Unknown keys are rejected. The MCP address is always `/mcp` on the app's origin.
